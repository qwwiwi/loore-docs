## Ключ

Ключ создаётся в кабинете: **[app.loore.ai](https://app.loore.ai) → Настройки → API и MCP**.

- Один ключ авторизует **обе** двери — MCP и REST.
- Плейнтекст показывается **один раз при создании**. На сервере хранится только его хэш, восстановить значение невозможно — потерял, выпусти новый и отзови старый.
- Ключей может быть несколько: удобно держать отдельный на каждого агента и отзывать по одному.

## Как передаётся

Только заголовком:

```http
Authorization: Bearer <ключ>
```

Никаких ключей в URL и в query-параметрах — сервер их не принимает: такой адрес утекает в логи, историю браузера и реферер.

<CodeGroup>

```bash REST
curl -X POST https://mcp.loore.ai/v1/ig-analytics \
  -H "Authorization: Bearer $LOORE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"handle":"@brand"}'
```

```json MCP-клиент
{
  "mcpServers": {
    "loore": {
      "type": "http",
      "url": "https://mcp.loore.ai/mcp",
      "headers": { "Authorization": "Bearer <ВАШ_КЛЮЧ>" }
    }
  }
}
```

</CodeGroup>

## Что делать с ключом

<Warning>
  Ключ — это доступ к вашему балансу. Он не должен попадать в git, в скриншоты и в историю оболочки.
</Warning>

- Храните в переменной окружения (`LOORE_API_KEY`) или в хранилище секретов вашего агента.
- В командах используйте подстановку переменной, а не сам ключ: то, что вы напечатали в терминале, остаётся в `~/.bash_history`.
- Клиенты, которые умеют это сами (например Hermes), спрячут ключ в свой `.env` — им и доверьте.
- Утёк — отзовите в кабинете. Отзыв мгновенный.

## Отказы

| Код | Что значит | Что делать |
| --- | --- | --- |
| `401` | ключа нет, он отозван или испорчен | проверьте заголовок целиком: схема `Bearer`, пробел, значение |
| `403` | ключ живой, но у него нет прав на этот метод | метод вне области ключа или тарифа |
| `402` | закончились запросы по тарифу | пополнить или дождаться нового периода |
| `429` | слишком часто | притормозить и повторить с задержкой |

Подробнее — в [ошибках](/concepts/errors).
